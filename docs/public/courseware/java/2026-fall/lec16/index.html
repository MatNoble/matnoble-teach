服务端：先等连接，再逐行回复

TcpGreetingServer.java 完整程序 · 37 行 
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.InetSocketAddress;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class TcpGreetingServer {
    public static void main(String[] args) throws Exception {
        int port = args.length == 0 ? 16016 : Integer.parseInt(args[0]);
        try (ServerSocket listener = new ServerSocket()) {
            // 本机实验，只监听回环地址。
            listener.bind(new InetSocketAddress("127.0.0.1", port));
            listener.setSoTimeout(90_000);
            System.out.println("正在监听 127.0.0.1:" + port);

            try (Socket peer = listener.accept()) {
                peer.setSoTimeout(8_000);
                BufferedReader in = new BufferedReader(new InputStreamReader(
                        peer.getInputStream(), StandardCharsets.UTF_8));
                BufferedWriter out = new BufferedWriter(new OutputStreamWriter(
                        peer.getOutputStream(), StandardCharsets.UTF_8));

                String line;
                // 读到一行就回复，客户端关闭输出后读到 null。
                while ((line = in.readLine()) != null) {
                    System.out.println("服务端收到：" + line);
                    out.write("ECHO: " + line + "\n");
                    out.flush();
                }
                System.out.println("客户端已结束发送");
            }
        }
    }
}
SERVER · 对照左边的序号
  1. ①

    绑定 127.0.0.1:16016，打印「正在监听」。

  2. ②

    accept() 停在这里等客户端；连上后返回 peer，相当于接起电话后手里的听筒。

  3. ③

    readLine() 等到客户端发来一行才继续。

  4. ④

    写回 ECHO: 加这一行和换行，再 flush()。

  5. ⑤

    readLine() 返回 null：客户端结束发送，服务端随后关闭。

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.InetSocketAddress;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class TcpGreetingClient {
    public static void main(String[] args) throws Exception {
        int port = args.length == 0 ? 16016 : Integer.parseInt(args[0]);
        try (Socket socket = new Socket()) {
            socket.connect(new InetSocketAddress("127.0.0.1", port), 3_000);
            socket.setSoTimeout(8_000);
            BufferedWriter out = new BufferedWriter(new OutputStreamWriter(
                    socket.getOutputStream(), StandardCharsets.UTF_8));
            BufferedReader in = new BufferedReader(new InputStreamReader(
                    socket.getInputStream(), StandardCharsets.UTF_8));

            String message = "hello java";
            // 换行是本实验约定的消息结束标记。flush 把暂存文字交给下游。
            out.write(message + "\n");
            out.flush();
            System.out.println("客户端收到：" + in.readLine());
        }
    }
}

  2. ③

    写出 hello java 和换行，flush() 交出去。

  3. ④

    readLine() 等服务端的一行回复，拿到后打印。

  4. ⑤

    try 结束，socket 自动关闭，相当于挂断。

回看程序 · 对照两端

监听用 ServerSocket，收发用 Socket

服务端代码片段 · TcpGreetingServer.java
listener.bind(new InetSocketAddress(
        "127.0.0.1", port));
Socket peer = listener.accept();

accept() 由服务端调用，在这里等待客户端连接；连接建立后返回这次会话的 Socket。

客户端代码片段 · TcpGreetingClient.java
socket.connect(new InetSocketAddress(
        "127.0.0.1", port), 3_000);

connect() 由客户端调用，向指定地址和端口发起连接；连接建立后，这个 Socket 就能读写。3_000 是最多等待的毫秒数。

对象谁使用负责什么用电话打比方
ServerSocket只有服务端绑定端口、等待连接（bind、accept），本身不收发数据桌上那部绑定了号码、守着等来电的电话
Socket两端各一个收发数据：getInputStream()、getOutputStream()，用完 close()接通后手里的听筒
这里的服务端只处理一次连接，结束后连监听也一起关闭。

概念 · 把名词说清楚

TCP 是什么：一条可靠的字节流水线

定义

TCP（Transmission Control Protocol，传输控制协议）：规定两个程序如何先建立连接、再可靠地交换字节流的通信协议。Socket / ServerSocket 是 Java 里使用它的入口。它建在 IP 之上：IP 只管把一个个数据包尽力送到对方机器，TCP 在这之上补足顺序和可靠。

TCP 保证
  • 先建立连接，再收发——下一页的三次握手。
  • 字节不丢、不重、按发送顺序到达。
  • 双向同时可用：两边都能发、也都能收。
TCP 不管
  • 不保留每次 write 的边界——任务二验证。
  • 不管字节代表什么：数字、文字还是别的，含义由两端约定。
  • 一行在哪里结束：换行是任务一里我们自己定的约定。
任务一的换行、任务二的 2 字节数组，都是应用程序自己的约定；TCP 提供的只是这条可靠的字节流水线。

回看程序 · 从字节到一行

换行和 flush 各管什么？

发送端 · 写的一侧
out.write(message + "\n");
out.flush();

换行约定了“这句说完了”。flush() 把暂存的文字交给下游输出流。

接收端 · 读的一侧
String line = in.readLine();

读到行结束或流结束才返回。电话里的声音是连续的，“一句到哪里结束”是两个程序事先约定的。

和第 15 讲一样，两边使用 UTF-8。flush() 只是把数据交出去，不代表对方已经处理；要等对方读到并回复，这一句才算说完。

机房实操 · 只改一行

为什么会等到超时？

先预测，再让两个程序验证
  1. 把客户端的 out.write(message + "\n") 改成 out.write(message)，保留 flush()。
  2. 重新运行两个程序，先服务端后客户端。先预测：两端各会停在哪一行？大约 8 秒后观察结果。
  3. 恢复换行重跑，确认原来的回声恢复。
做完实验后核对

字节可以到达，但服务端仍在等行的结尾：readLine() 没有返回。客户端同时在等回复。两端都在等对方，直到 8 秒超时。

典型输出：两端各报 java.net.SocketTimeoutException: Read timed out，服务端指向第 28 行的 readLine()，客户端指向第 24 行。一端先关闭后，另一端也可能读到流结束而不是超时。

这就像拨通以后，一方一直没说“OVER”：对方不知道这句讲完没有，只能干等。

服务端：按实际长度读取

TcpBytesServer.java 完整程序 · 30 行 
import java.io.InputStream;
import java.net.InetSocketAddress;
import java.net.ServerSocket;
import java.net.Socket;
import java.util.HexFormat;

public class TcpBytesServer {
    public static void main(String[] args) throws Exception {
        int port = args.length == 0 ? 16016 : Integer.parseInt(args[0]);
        try (ServerSocket listener = new ServerSocket()) {
            listener.bind(new InetSocketAddress("127.0.0.1", port));
            listener.setSoTimeout(90_000);
            System.out.println("正在监听 127.0.0.1:" + port);
            try (Socket peer = listener.accept()) {
                peer.setSoTimeout(8_000);
                InputStream in = peer.getInputStream();
                byte[] buffer = new byte[2]; // 每次最多读 2 字节，便于观察。
                int count;
                int total = 0;
                while ((count = in.read(buffer)) != -1) {
                    System.out.println("本次 " + count + " 字节：" +
                            HexFormat.ofDelimiter(" ").withUpperCase()
                                    .formatHex(buffer, 0, count));
                    total += count;
                }
                System.out.println("接收结束，共 " + total + " 字节");
            }
        }
    }
}
SERVER · 对照左边的序号
  1. ①

    数组装 2 格，所以每次最多读 2 字节。这是程序的设置，不是 TCP 的规定。

  2. ②

    read() 返回本次实际读到的数量，存进 count；返回 -1 表示对方结束发送。

  3. ③

    只格式化前 count 个：数组里后面的格子是上一次留下的旧字节。

客户端：两次写入六个字节

import java.io.OutputStream;
import java.net.InetSocketAddress;
import java.net.Socket;

public class TcpBytesClient {
    public static void main(String[] args) throws Exception {
        int port = args.length == 0 ? 16016 : Integer.parseInt(args[0]);
        try (Socket socket = new Socket()) {
            socket.connect(new InetSocketAddress("127.0.0.1", port), 3_000);
            OutputStream out = socket.getOutputStream();
            byte[] data = {0x68, 0x65, 0x6C, 0x6C, 0x6F, 0x21}; // hello!
            out.write(data, 0, 3); // 前 3 字节
            out.write(data, 3, 3); // 后 3 字节
            out.flush();
            socket.shutdownOutput(); // 告诉服务端：本次不再发送字节。
            System.out.println("已发送 6 字节，结束发送");
        }
    }
}

  1. ①

    分两次写，每次 3 字节：先 68 65 6C，再 6C 6F 21。

  2. ②

    shutdownOutput() 告诉服务端“我不再发送了”，对方的 read() 随后返回 -1。

两次写入，接收端怎样装进数组？

发送端 · 两次 write，各 3 字节
68656C＋6C6F21

两次写入的字节进入同一条连接后首尾相接，中间没有“这是第几次写的”标记。

68656C6C6F21

像一条连续的传送带：能保持先后顺序，不保留每次写入的格子。

接收端 · 每次最多读 2 字节

    实心格是本次读到的字节，即数组的前 count 个；虚线格是数组里上一次留下的旧字节，所以代码只格式化前 count 个。右边的读取过程是按规则生成的模拟，你的程序输出以实际为准。
